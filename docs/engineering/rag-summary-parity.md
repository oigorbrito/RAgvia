## Local evidence

The supplied ZIP fixture was evaluated without printing or persisting its case text and without a provider call. Reproduce from the repository root with `python scripts/evaluate_rag_summary_parity_fixture.py --archive <path-to-rag_resumo.zip>`. On Windows/Python 3.12.10, the observed archive SHA-256 matched the reference identity above and the machine-readable aggregate was: one input case; three parties; one representative; three subjects; 13 movements; one scheduled-hearing annotation; four explicit-period annotations. This is supplied-fixture parsing evidence only, not live Judit precision or legal-quality evidence.

The provider-free synthetic RAG baseline was rerun using `python -m scripts.evaluate_synthetic_rag --check-baseline`. Dataset: `tests/eval/synthetic_cases.json`, version `synthetic-30-v1`, recorded dataset Git blob `78c31e818fa8dd78f7b1468aab8f34fdb3a98ad8`. Environment: Windows, Python 3.12.10. Baseline check passed (30 synthetic cases); metrics remained at the committed thresholds: unsupported assertions 0.05, milestone recall 0.90, inconsistency-detection recall 0.9444444444444444, attention false-positive rate 0.05263157894736842. The reproducibility metadata and compact machine-readable result are in `docs/evaluation/rag-summary-parity-run.json`. This does not establish live-provider quality. The command makes no paid provider calls.

## Compatibility and privacy

New structured documents use schema version 3 with a required allowlisted `representatives` projection. Version 2 documents remain canonical as legacy records and may omit it, even when the current process has representatives; the historical summary remains readable while a later generation can publish the new projection. New header fields are additive and only admitted from the non-secret source allowlist. The secret-process header and deterministic local-summary path are not expanded. The new representative/header facts are rendered from the allowlisted local projection and excluded from the provider payload; representative document/OAB values are omitted. Validation separately permits only a successfully parsed ISO distribution date from that deterministic header, without adding it to provider context. No raw provider payload, donor fixture, personal case data, or donor runtime dependency is added.

The prompt version changes because the public prompt now recognizes the additional source metadata and the deterministic output gains a section. Deployment operators should account for the existing version-based refresh behavior; this change does not claim a cost-free reprocessing plan.

## Scope of completion

This is minimum, partial parity—not equivalence to the donor output. Broader movement-date/deadline patterns and speculative metadata alerts remain gaps by design. The narrow movement annotations are synthetic-test evidence only, not proof of real-source precision. A future iteration should expand them only with source-specific, adversarial false-positive evidence.
