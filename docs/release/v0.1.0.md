# Rpy v0.1.0

Primeiro release offline qualificado do Rpy.

## Escopo

- FastAPI + PostgreSQL 16 + pgvector;
- ingestão Judit assíncrona com versionamento e idempotência;
- fila PostgreSQL com `FOR UPDATE SKIP LOCKED`, heartbeat, retry e reclaim;
- retrieval BM25 + pgvector para processos com mais de 40 movimentos;
- geração/validação de resumo com providers externos no modo real;
- caminho determinístico provider-free para processos sob sigilo;
- multitenancy e isolamento por tenant;
- audit log e retenção/expurgo;
- frontend server-rendered com harness comportamental executável;
- smoke offline de release sem credenciais pagas;
- distribuição do projeto sob licença MIT, com provenance/atribuições registradas em `NOTICE`.

## Evidência de release

O `main` foi qualificado com:

- project harness, incluindo guardrails especializados de migration/release;
- static Python quality checks;
- dependency consistency (`pip check`);
- unit tests;
- frontend behavior tests;
- container image smoke;
- PostgreSQL backup/restore drill;
- PostgreSQL integration tests;
- offline release smoke;
- fresh clone externo no Windows com rebuild completo da imagem, migrations 001-014 e saída:

```text
RPY OFFLINE SMOKE: PASS
process=0000000-00.2026.8.21.0001
summary=valid
jobs=complete
providers=0
```

## Provider acceptance

Judit, Anthropic, OpenAI e Cohere reais permanecem como aceitação controlada pós-release e ambiente-específica; BGE real exige artifact/evidência operacional próprios. Nada disso é executado no CI. O procedimento canônico está em `docs/release/provider-acceptance.md`.

## Operação

Windows:

```powershell
.\scripts\smoke_offline.ps1
```

Unix:

```bash
./scripts/smoke_offline.sh
```

Consulte `docs/deployment/`, `docs/release/offline-release-candidate.md`, `LICENSE` e `NOTICE` para operação, critérios de release, termos do projeto e provenance de terceiros.
